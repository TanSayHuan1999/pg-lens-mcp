## Why this wins in interviews

- Missing indexes are only half the story. Unused / duplicate indexes tax every
  INSERT/UPDATE (write amplification), waste storage, and slow the planner.
  Knowing both sides is production DBA thinking, not tutorial knowledge.
- Direct response to real external feedback: Glama's evaluator flagged
  "no global index view / no unused-duplicate detection" (2026-11-22).
  Interview story: external review -> scoped feature -> tests/evals -> release.
- Pure Postgres depth interviewers can probe: pg_stat_user_indexes,
  pg_index, indisprimary / indisunique, pg_relation_size.

## New tool: `index_health` (tool #6)

Input: optional `schema` (default: all user schemas).

For every index in user schemas, return:
- schema, table, index name, columns, size bytes
- idx_scan (times used), is_primary, is_unique
- verdict:
  - `unused` — idx_scan = 0 AND not primary AND not unique
    (PK/unique are never flagged: they enforce integrity even if never scanned)
  - `redundant` — another index on same table covers this index's columns
    as a left-prefix (e.g. (customer_id) is redundant if (customer_id, status) exists),
    excluding exact PK/unique duplicates handling carefully
  - `ok` — otherwise
- summary counts + total wasted bytes (unused + redundant sizes)
- Suggestions only, same philosophy as suggest_indexes:
  text like `DROP INDEX CONCURRENTLY ...; -- review first`
  pg-lens NEVER drops anything.

Data sources (all read-only catalog queries, same BEGIN READ ONLY wrapper):
- pg_stat_user_indexes (idx_scan)
- pg_indexes / pg_index + pg_attribute (columns, indisprimary, indisunique)
- pg_relation_size(index) for size

Duplicate/redundant logic goes in a pure function (unit-testable without DB),
mirroring src/plan.ts structure.
